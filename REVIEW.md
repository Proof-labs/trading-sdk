# REVIEW.md: trading-sdk

This extends `Proof-labs/.github` [REVIEWING.md](https://github.com/Proof-labs/.github/blob/main/REVIEWING.md) and does not relax it.

## Invariants

- **Signed bytes are engine-identical.** Envelope `[version=2, action_type, seq, payload, pubkey, signature]`; the signature covers the `ProofExchange-v3` domain prefix, the 32-byte `chain_id`, `action_type`, `seq` and payload. Two version numbers, never conflated (`CLAUDE.md`, `src/codec.ts`, `src/crypto.ts`).
- **Messages are positional MessagePack arrays.** Field order is the layout; new fields go at the end as optional (`CLAUDE.md`).
- **One codec, in Rust.** Actions encode and proof-wire reads decode in `crates/proof-trading-sdk` through WASM (TS) and PyO3 (Python). TS and Python only rename fields; they never hand-decode a proof-wire type (`CLAUDE.md`, `crates/proof-trading-sdk-wasm/src/lib.rs`).
- **Every binding reproduces the checked-in vectors.** `conformance/*.ndjson` comes from `gen-vectors`, CI fails if regenerating changes it, and the Rust, Python and TS runners must match every byte (`conformance/README.md`, `.github/workflows/ci.yml`).
- **Money is integer micro-USDC; quantities are integer contracts.** No floats, no loss of `u64` precision (`CLAUDE.md`).
- **Gateway only.** All submission, reads, tx status, chain status and streams go through `gatewayUrl`. `useGateway: false` stays a non-default internal path (`CLAUDE.md`, `src/client.ts`).
- **The gateway API key never leaves the gateway origin.** A read path that resolves to another origin is refused (`crates/proof-sdk-rs/src/info.rs`).
- **Key material never reaches logs or errors**, and typed errors replace string matching (`CLAUDE.md`, `src/errors.ts`).
- **Each package versions on its own, at `>= 1.0.0`,** classified against the wire: PATCH no wire change, MINOR additive and still decodable, MAJOR anything that breaks decode either way (`CLAUDE.md`).

## Consumers

- **npm `@proof-labs/trading-sdk`:** `Proof-labs/Web-UI`, `Proof-labs/WebAdmin` (app and `cli/`), `Proof-labs/proof-market-maker`, `Proof-labs/proof-integration`. Check: search each for the changed export, union or method, and list each break with its fix and the merge order.
- **Python `proof-trading-sdk` and Rust `proof-sdk-rs` / `proof-trading-sdk`:** external and in-cluster callers. Check: the binding's own semver bump and CHANGELOG line, separate from the npm one.
- **Upstream contracts:** `Proof-labs/wire` (the `proof-wire` git rev in `crates/proof-trading-sdk/Cargo.toml`) and the `Proof-labs/api-gateway` routes and `openapi.yaml`. Check: the pin is a merged revision, the changed shape matches the producer at that revision, and the PR's "Wire-format / spec impact" section says so.

## Recurring failures

- **A wrong semver class.** A removal or decode break shipped as MINOR, or one binding's break not marked as that binding's major. Resolved: each changed package gets its own correct bump and CHANGELOG line.
- **An incomplete consumer list.** A widened union or removed method breaks callers the merge-order section does not name. Resolved: every downstream break is named with its fix, and a narrowing helper is exported where callers would otherwise cast.
- **A decoder that drifts from its producer.** It rejects the producer's real representation (a null field, an omitted trailing field, an `Unknown` variant) and fails the whole read. Resolved: the decoder follows the producer's actual omission and variant rules, with a test on producer-shaped bytes.
- **Fixtures that do not come from the producer.** Hand-written attributes, retired response shapes or frame sequences the server never sends, so the test passes against a broken decoder. Resolved: fixtures are generated by the canonical encoder or shared conformance vectors, run through the public entry point.
- **Independent decoders with no shared corpus.** TS, Python and Rust each decode the same type differently. Resolved: one shared accept/refuse vector set runs in every affected binding.
- **A mock that ignores its request.** A paging or window mock returns the same rows for any bound, hiding skips and duplicates. Resolved: the mock serves by the requested window and the test asserts complete, non-duplicated output.
- **Stream outcomes collapsed.** Permanent refusals retried forever, a refused subscription leaving the caller blocked, a closed stream iterating empty, backoff reset only on data. Resolved: each terminal and retry outcome is specified and tested, and the subscription acknowledgement counts as recovery.
- **A deadline that does not bound the request.** Elapsed time is checked after a network call, so a wait exceeds its budget. Resolved: check before each poll and bound each request by the remaining deadline.
- **An ambiguous submit loses its hash.** A helper drops the transaction hash on timeout or transport error, so the caller cannot reconcile without resubmitting. Resolved: the hash is in the typed outcome or error.
- **A credential sent to another origin.** A caller-supplied absolute URL reuses the credentialed client. Resolved: scheme, host and port are pinned to the gateway, with tests for malicious URL forms.
- **Docs that overclaim.** README, docstrings or bug notes claim parity, shapes or causes the code does not have. Resolved: each claim traces to code or a cited run.

## Not findings here

- Local validation that duplicates engine policy, or guarantees the engine and gateway do not document.
- An internal refactor treated as a public contract change when bytes and exports are identical.
- Retry, pacing or deadline policy missing from the default TS HTTP path: the pluggable transport owns it by design (`src/http-transport.ts`).
- Validator signature or payload-proof verification for finalized reads that document they return trusted gateway observations.
- Stronger finality, pagination or delivery guarantees than the read's agreed contract.
- Exhaustive branch coverage, duplicate tests or mutation testing on every change.
- A preferred abstraction or small duplication with no shown behaviour or maintenance cost.
- An activation step or routine engineering choice raised as a merge blocker or a decision row.

## Repository rules

- **X1 Conformance regenerated.** A change to the Rust codec, signing or events regenerates `conformance/*.ndjson` with `gen-vectors` in the same PR, and re-diffs `crates/spec/golden-vectors/*.hex` after a wire change.
- **X2 Cross-binding parity.** A new read or decoder in one binding either matches the existing behaviour in the others, through shared vectors, or the PR names the gap and why it is left.
- **X3 Per-package release class.** The PR states the semver class for each package it changes, with the compatible engine or proof-wire version, and leaves unchanged packages at their version.
